# 管理员容量配置

本文定义管理员调整区域控制面容量的正式入口。容量变更不修改源码，不重新构建镜像或
wheel，也不发布 Aurora 动态配置 revision；CLI 复用当前已验签 release，只生成带独立
配置摘要的 config-only release，并滚动受影响的 CPU 角色。

## 1. 支持范围

当前管理员可配置：

- control-worker 副本数；
- telemetry spool enabled/disabled 和 spool-worker 副本数；
- remediation budget 的 Region、cluster、node、failure domain 和 resource class
  上限。

凭据、Region、cluster identity、Runtime Profile、operation allowlist、release pin、
破坏性能力开关和安全不变量不属于通用管理员配置。不得把任意 `GPU_FAULT_*` 变量写入
配置文件后透传给 Pod。

## 2. 使用预设

查看并生成计划：

```bash
gpu-fault-admin capacity plan \
  --state-dir /secure/gpu-fault \
  --preset 32-disabled
```

支持的预设：

| preset | Region budget | 每集群 | 每 resource class | spool |
|---|---:|---:|---:|---|
| `default` | 20 | 5 | 2 | disabled，0副本 |
| `32-disabled` | 128 | 4 | 4 | disabled，0副本 |
| `32-enabled` | 128 | 4 | 4 | enabled，3副本 |
| `50-disabled` | 200 | 4 | 4 | disabled，0副本 |
| `50-enabled` | 200 | 4 | 4 | enabled，3副本 |

计划写入`<state-dir>/admin-config/plan.json`，并输出：

- 当前值、目标值和逐字段差异；
- 站点可读身份及其摘要；
- 当前签名release ID、Manifest SHA和staging等级；
- 当前和目标全局配置摘要；
- ingress、worker、spool 三个角色摘要；
- 实际需要滚动的角色；
- `plan_sha256`。

审核计划并取得变更单或维护窗口批准后执行：

```bash
gpu-fault-admin capacity apply \
  --state-dir /secure/gpu-fault \
  --plan-sha256 <reviewed-plan-sha256> \
  --reference CHG-12345
```

`apply`先持锁校验计划、站点身份和当前配置 baseline，再把目标值持久化到
`admin-config/desired.json`。发布失败时计划和审批保留，可用相同参数幂等续跑；成功
完成 verify、stability 和 commit 后，活动计划被消费，审计保存在
`admin-config/history/<plan-sha256>/`。

## 3. 显式参数

不使用预设时可组合以下参数：

```bash
gpu-fault-admin capacity plan \
  --state-dir /secure/gpu-fault \
  --control-worker-replicas 6 \
  --spool disabled \
  --spool-replicas 0 \
  --max-active-region 128 \
  --max-active-per-cluster 4 \
  --max-active-per-node 1 \
  --max-active-per-failure-domain 1 \
  --max-active-per-resource-class 4
```

未填写字段继承当前持久化值。`--preset default`用于显式恢复当前release默认值。
CLI拒绝未知字段、错误类型、spool开关与副本不一致、node/failure-domain上限大于1、
cluster/resource-class大于Region，以及超过已验收PostgreSQL fleet连接预算的组合。

## 4. 配置文件

首次建站可在仓库外准备权限`0600`的YAML：

```yaml
apiVersion: gpu-fault.aws/v1alpha1
kind: AdminConfig
spec:
  capacity:
    preset: 32-disabled
    controlWorkerReplicas: 6
    remediation:
      maxActiveRegion: 128
      maxActivePerCluster: 4
      maxActivePerNode: 1
      maxActivePerFailureDomain: 1
      maxActivePerResourceClass: 4
    telemetrySpool:
      enabled: false
      replicas: 0
```

随后执行：

```bash
gpu-fault-admin deploy \
  --cpu-cluster-arn <cpu-arn> \
  --gpu-cluster-arn <gpu-arn> \
  --state-dir /secure/gpu-fault \
  --admin-email <operations-email> \
  --config /secure/gpu-fault-input/admin-config.yaml
```

首次部署未提供`--config`时，CLI把release默认值持久化到state。已有站点不允许通过
`deploy --config`直接改变配置；必须先运行：

```bash
gpu-fault-admin config plan \
  --state-dir /secure/gpu-fault \
  --file /secure/gpu-fault-input/admin-config.yaml

gpu-fault-admin config apply \
  --state-dir /secure/gpu-fault \
  --plan-sha256 <reviewed-plan-sha256> \
  --reference CHG-12345
```

文件中未出现的字段继承当前持久化值。普通升级不传文件时同样保持当前值，不会意外
恢复默认。

## 5. 生效与回滚

配置摘要独立于代码 release ID、镜像摘要和wheel摘要。config-only release：

- 不上传或重建任何代码制品；
- 不执行schema、GPU数据面、Node Runtime或Runtime Profile阶段；
- 不发布cluster registry revision；
- remediation budget或worker副本变化只滚control-worker；
- spool启用先滚spool-worker，再滚ingress；
- spool禁用先关闭ingress admission，等待spool depth和leased都为0，再缩容
  spool-worker；
- release state和Deployment metadata记录全局配置摘要，Pod template记录角色摘要，
  ConfigMap变化不会被误判为`NOOP`。

发布器在变更前保存角色ConfigMap。verify或stability失败时沿用现有自动回滚，恢复旧
ConfigMap并重启角色。只执行`kubectl rollout undo`不构成配置回滚。

## 6. 热更新边界

当前配置通过环境变量在进程启动时加载，因此容量配置使用Kubernetes滚动生效，不支持
通用无重启热更新。副本数、Uvicorn进程、线程池、PostgreSQL pool和spool拓扑也不适合
在线热改。

若未来确实要求部分阈值不重启即时生效，必须另行实现配置revision、全进程ACK、
mixed-revision门禁、失败回滚和状态指标。该机制不得复用cluster registry记录，也不得
绕过本文件的字段白名单和审批。
